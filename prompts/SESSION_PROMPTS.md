# Промты для оператора

Не изобретай формулировки на ходу — агент хорошо следует готовым.

## P1. Старт сессии (всегда первым)
```
Читай AGENTS.md, затем последние записи CHANGELOG_AI.md, затем раздел BACKLOG для этапа <Mx>.
Ответь четырьмя строками: этап, задача, критерий приёмки, что будешь менять в файлах.
Не пиши код до подтверждения этого плана.
```

## P2. Начать этап
```
Выполни этап <Mx>, задачи <Bx.y>. Не переходи к задачам следующего этапа.
После кода покажи вывод pytest и mypy. Заполни CHANGELOG_AI.md по формату.
Если чего-то не знаешь (имя метода API, лимит) — пиши TODO(VERIFY), не выдумывай.
```

## P3. Проверка честности
```
Покажи список всех TODO(VERIFY) в репозитории и объясни по каждому, где именно
надо сверить с документацией. Скажи, какие из этих мест ты мог бы закрыть сам и почему не закрыл.
```

## P4. Анти-галлюцинационная проверка
```
Перечисли все вызовы Tinkoff Invest API, которые ты использовал. Для каждого укажи:
подтверждено документацией / SDK в окружении / взято из догадки.
Третье запрещены AGENTS.md — исправь.
```

## P5. Коррекция: деньги
```
Ты использовал float для денег в <место>. Перепиши на Decimal, добавь тест,
ловящий регресс. Покажи, что изменится в расчёте на пограничном кванте.
```

## P6. Коррекция: обработка ошибок
```
В <место> стоит `except Exception: pass`. Перепиши: лог с контекстом, явная стратегия
повтора, уведомление в VK при критичном. Покажи тест, воспроизводящий сбой.
```

## P7. Коррекция: риск
```
Докажи, что ни один внешний вызов не может увеличить risk_per_trade или снять лимит потерь.
Если такая возможность есть — закрой её и добавь тест, запрещающий регресс.
```

## P8. Коррекция: объём
```
Ты сделал больше, чем просили. Откати лишнее, вернись к границам этапа, перепиши CHANGELOG
так, чтобы он отражал реально сделанное.
```

## P9. Требование доказательства
```
Не описывай, что работает. Покажи: вывод тестов, вывод mypy, и ручной прогон на
синтетических данных с ожидаемыми числами, которые ты посчитал заранее.
```

## P10. Приёмка этапа
```
Сверь этап <Mx> с docs/15_ACCEPTANCE.md пункт за пунктом. Для каждого пункта —
подтверждение (файл/тест/команда) или честное «не выполнено». Ничего не помечай принятым без доказательства.
```

## P11. Подготовка к M8 (реальные заявки)
```
Этап M8 меняет класс рисков. Подготовь: (1) список того, что может пойти не так и потерять деньги,
(2) доказательство, что paper-режим проверен на 200+ сигналах, (3) план откатa,
(4) конфиг с консервативными лимитами на первый день live. Код заявок пока не пиши.
```

## P12. Ретроспектива
```
Посмотри CHANGELOG за весь проект и назови 3 места, где ты сам не уверен в корректности.
Проранжируй по потенциальному финансовому ущербу. Предложи, как каждое проверить.
```
