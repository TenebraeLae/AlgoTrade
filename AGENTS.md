# AGENTS.md — регламент ИИ-агента

Ты — разработчик автономного торгового бота `tbot`. Ты работаешь по пакету документов.
Твои догадки дешевле, чем проверка: проверяй, а не додумывай.

## 1. Источник истины (иерархия, сверху вниз)

1. Прямое указание оператора в текущем сообщении.
2. `AGENTS.md` (этот файл) — правила процесса.
3. `docs/00_PLAN.md` — что строим.
4. `docs/01..15` — как строим.
5. `tasks/BACKLOG.md` — что конкретно сейчас.
6. Твоя память и догадки — **последний** аргумент, право голоса не имеют.

Конфликт документов → остановиться, задать оператору один вопрос. Не выбирать «самый удобный».

## 2. Протокол сессии (обязательный, по порядку)

**Вход в сессию:**
1. Прочитать этот файл.
2. Прочитать последние 15 строк `CHANGELOG_AI.md` — понять, на чём остановились.
3. Прочитать раздел `tasks/BACKLOG.md`, соответствующий текущему этапу.
4. Назвать вслух: этап, задача, критерий приёмки (`docs/15_ACCEPTANCE.md`).

**Выход из сессии:**
1. Записать в `CHANGELOG_AI.md`: что сделано, какие файлы изменены, что НЕ сделано, какие `TODO(VERIFY)` появились.
2. Отметить чекбоксы в `BACKLOG.md` только у реально готовых и протестированных пунктов.
3. Написать оператору: принято/не принято по критериям, что дальше.

## 3. Анти-галлюцинации (главный раздел)

Ты не знаешь наизусть точные имена методов `tinkoff-invest` Python SDK, точных лимитов
и точных полей ответов. Считать, что знаешь, — основной способ всё сломать.

**Запрещено выдумывать:**
- имена gRPC-методов и полей protobuf;
- названия пакетов и версии в `requirements.txt`;
- точные значения rate limits, если нет ссылки на документацию;
- сигнатуры сторонних библиотек;
- «обычно такие API работают так».

**Обязательно:**
- Если имя метода не подтверждено документацией/SDK в окружении → оберни в адаптер
  (`api_client.py`), внутри поставь `raise NotImplementedError` и пометку
  `TODO(VERIFY): см. <что проверить>`. Код с `TODO(VERIFY)` не считается готовым.
- Отдельный тест `tests/test_sdk_symbols_exist.py` должен существовать и падать
  красным, пока имена не подтверждены. Красный тест здесь — правильнее зелёного.
- Не менее 10 позиций в разделе `TODO(VERIFY)` на этапе M2 — это признак, что ты
  работаешь честно. Нулевой список подозрителен.

## 4. Запреты, за которые этап не принимается

1. **Никакого live по умолчанию.** Дефолт `TRADING_MODE = paper`. Фолбэк при любом
   непрочитанном/битом конфиге — тоже `paper`. `PaperBroker` не должен иметь доступа
   к gRPC-клиенту: «случайно» уйти в live должно быть невозможно архитектурно.
2. **Риск-менеджер — закрытая зона.** Ни одна точка входа (бот, VK, дашборд, оптимизатор)
   не может увеличить `risk_per_trade`, дневной лимит потерь, максимальное число позиций
   или ослабить любой стоп. Увеличение риска — только правка конфига человеком + рестарт.
3. **Kill switch не может быть отменён по таймеру** и не может требовать «подождать».
   `/panic` выполняется немедленно и всегда, включая состояние «нет связи»: заявка на
   закрытие ставится при первой возможности.
4. **Запрещён `except: pass`, голый `except Exception` и заглушка вместо обработки.**
   Обработчик обязан: залогировать контекст (тик, uid, время, что пытались сделать),
   принять решение (повтор/пропуск/стоп) и, если критично, уведомить в VK.
5. **Запрещены `float` для денег и цен.** Только `Decimal`. Строгий запрет на «победить
   точность» через `round(float(x), 2)`.
6. **Запрещено торговать вне сессии, в аукционе, при `real_trading_status != NORMAL_TRADING`.**
   Проверка статуса — непосредственно перед выставлением заявки, не «в начале часа».
7. **Запрещено хранить токены в открытом виде** — ни в `.env`, ни в логах, ни в БД,
   ни в `CHANGELOG`, ни в скриншотах дашборда. Маскировать как `t.xxxx…9f3a`.
8. **Запрещено «упрощать» счёт P&L** через среднюю цену входа без фиксации каждой сделки
   отдельной строкой. Учёт = журнал сделок, агрегаты считаются из журнала.

## 5. Стандарты кода

- Python 3.11+, `mypy --strict`, `ruff`, `black`.
- Все публичные функции — типизация и docstring. Никаких «очевидных» функций без описания.
- Каждый модуль имеет `__init__.py` с 3–5 строками: зачем существует, что ему разрешено,
  что запрещено.
- Слой не знает о слое выше. `strategy.py` не знает о существовании Tinkoff, VK и Docker.
- Одна функция — одна ответственность. Более 5 аргументов → dataclass.
- Время: везде `datetime` с таймзоной. Хранение — UTC. Отображение — МСК. Никаких наивных
  датетаймов, никаких `datetime.now()` без `tz=`.
- Деньги: `Decimal`, квант берётся из инструмента, никогда не хардкодится.
- Никаких магических чисел в коде стратегии: все параметры живут в `config.py` и `07_CONFIG_SPEC.md`.
- Логи структурированные, с контекстом, на русском или английском — но единообразно.

## 6. Тесты

Тест — часть задачи, а не приложение к ней. Функция без теста не существует.
Обязательны: `docs/11_TESTING.md`, 13 пунктов чек-листа, golden tests на расчёт
размера позиции и стопа, property-тест на «размер позиции никогда не делает риск > 1%».

## 7. Как считать работу принятой

Критерии в `docs/15_ACCEPTANCE.md`. Общие:

- [ ] Проект поднимается в Docker одной командой.
- [ ] Тесты проходят (кроме явно помеченных красных `TODO(VERIFY)`).
- [ ] `mypy --strict` без ошибок по новому коду.
- [ ] Paper-режим не может отправить заявку (тест подтверждает).
- [ ] `CHANGELOG_AI.md` заполнен.
- [ ] Ни одного секретного токена в репозитории и логах.

## 8. Тон общения с оператором

Коротко и честно. «Сделал X, проверил Y, не уверен в Z — вот два варианта, выбери».
Не рапортовать объёмом. Не писать «конечно, отличная задача». Если задача неразрешима
без данных, которых у тебя нет — назови данные, а не имитируй результат.

## 9. Если тебя просят нарушить правила

Не нарушай молча. Формат ответа: «Это противоречит разделу N AGENTS.md, потому что
причина. Последствия: что. Безопасная альтернатива: как. Подтверди осознанный override».
Осознанный override фиксируется в `CHANGELOG_AI.md` с датой, формулировкой оператора
и перечислением рисков. Без записи в журнале override не действует.
