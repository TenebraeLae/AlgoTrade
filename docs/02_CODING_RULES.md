# 02_CODING_RULES — стандарты

## Общая дисциплина

- Python 3.11+, `mypy --strict`, `ruff`, `black`, `pytest`.
- Все публичные функции типизированы и имеют docstring: что делает, что возвращает, при каком условии отказ.
- Каждый пакет — `__init__.py` на 3–5 строк: назначение, что разрешено, что запрещено.
- Одна функция — одна ответственность. Больше 5 аргументов → dataclass.
- Параметры стратегии только из конфига. Магическое число в коде стратегии — замечание.
- Размер модуля ориентир до 400 строк; выше — делить.

## Деньги и цены

- Только `Decimal`. Строка-конструктор из строки API: `Decimal(str(x))`.
- Квант и шаг цены — из `InstrumentInfo`, никогда не литерал.
- Округление объёма — вниз до целого лота (`ROUND_DOWN`). Округление вверх запрещено:
  оно увеличивает риск сверх расчётного.
- Сравнение цен — через `>=`/`<=` по Decimal, никогда через `round()` и `==`.
- Запрещены: `float` в сигнатурах денежного домена, `round(float(...))`, numpy-арифметика
  над ценами (numpy допустим только для индикаторов на массивах, результат — Decimal на выходе).

## Время

- Все `datetime` tz-aware. Хранение UTC, вывод МСК (`ZoneInfo("Europe/Moscow")`).
- `datetime.now()` без `tz` запрещён линтером (добавить правило/тест).
- Сравнение с сессией — через утилиты `utils.trading_session`, не в модуле стратегии.
- Любые «дельты» — `timedelta`, не секунды-магистикалы.

## Исключения

```python
# нельзя
except Exception:
    pass

# можно
except MarketDataUnavailable as e:
    log.warning("свечи недоступны", ticker=t, tf=tf, attempt=n, err=e)
    if n >= MAX_ATTEMPTS:
        notify("не удалось получить свечи, сигналы по тикеру пропущены")
        return None
    await backoff(n)
```
Иерархия: `TBotError` → `GatewayError`, `MarketDataUnavailable`, `RateLimited`,
`InsufficientFunds`, `TradingClosed`, `IntegrityError`.
Неизвестное исключение в торговом цикле → пауза новых заявок + уведомление. Не «продолжить как ни в чём не бывало».

## Логирование

Структурно: событие, уровень, контекст (тик, uid, tf, попытка, цена, lots).
Токены маскировать `t.xxxx…9f3a`. Никаких дампов полных ответов API в INFO.
Уровни: DEBUG — данные индикаторов; INFO — сделки, смена режима, оптимизация;
WARNING — лимиты, реконнект, пропуска сигналов; ERROR — сбои, расхождения учёта.

## БД и код

- Все изменения схемы — миграциями с номером, не ручными `ALTER TABLE` в рантайме.
- Никаких SQL-конкатенаций из пользовательских строк (VK-команды!). Только параметры.
- Каждой записи о сделке соответствует ровно одна строка в `trades`.
  Никаких «перезаписем позицию целиком».

## Git

Коммит = одна логическая задача из BACKLOG. Формат: `M5: risk_manager, формула позиции + golden-тесты`.
В коммите не смешивать стиль и логику. Красные тесты не коммитятся в main, кроме
явно помеченных `TODO(VERIFY)` с описанием в сообщении.

## Чего конкретно не делать (список, который часто нарушают)

1. Не писать «потом уберём TODO» — TODO убирается только проверкой.
2. Не добавлять `sleep(1)` вместо backoff.
3. Не делать `global` для состояния портфеля.
4. Не читать конфиг внутри функций — только инжект в конструктор.
5. Не логировать «успех» там, где может быть частичный успех.
6. Не считать P&L по средней цене входа, игнорируя комиссии.
7. Не писать тесты, которые всегда проходят (assert True, отсутствие assert).
