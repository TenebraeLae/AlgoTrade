# 11_TESTING — что обязано быть протестировано

Сеть во всех тестах недоступна. Брокер — мок `InvestGateway`. Данные — фикстуры.
Тест без assert или с `assert True` приравнивается к отсутствию теста.

## Ядерные инварианты (не могут быть сломаны никогда)

1. `PaperBroker` физически не может отправить заявку: у него нет gRPC-клиента.
   Тест инспектирует атрибуты/зависимости класса.
2. Дефолт и фолбэк режима — всегда `paper` (битый конфиг, нет файла, exception).
3. Риск одной сделки ≤ `RISK_PER_TRADE` + допуск на издержки, 1000 случайных наборов данных.
4. `risk_manager` не имеет публичного метода, увеличивающего риск или снимающего лимит.
5. Ни один внешний контур (VK, REST, оптимизатор) не меняет параметры риска.
6. Вне сессии/в аукционе/при статусе ≠ NORMAL_TRADING заявок нет.
7. В режиме `chaos` новых позиций нет.
8. Стоп не может быть перемещён против позиции.
9. Дневной лимит потерь останавливает торговлю ровно при превышении и не раньше.
10. Уровень L3 не имеет пути применения в live (тест на отсутствие функций/веток).
11. В логах и HTML нет подстрок, совпадающих с тестовым токеном.
12. Индикаторы не заглядывают в будущее (shift-тест).
13. Каждой сделке соответствует одна строка `trades` и одна `decisions`.

## Golden-тесты

Значения считаются заранее (рукой или независимой реализацией), фиксируются в JSON,
сравнение до 6 знаков.

| Что | Проверок |
|---|---|
| EMA, RSI, MACD, Bollinger, ATR, VWAP, ADX | ≥5 синтетических серий каждое |
| Размер позиции | 5 тиков с разными ATR, lot_size, ценой, балансом |
| Расчёт стопа/тейка/трейла | включая «безубыток с учётом комиссии» |
| P&L и чистый результат | с комиссией, проскальзыванием, частичными исполнениями |
| Перевод времени | UTC → МСК, переход через границу сессии, праздничный день |

## Тесты корректности учёта (M6)

FIFO при докупках; усреднение против позиции (разные стороны); закрытие части;
частичное исполнение → остаток; коррекция позиции при сплите; восстановление после
рестарта (20 сценариев, включая «позиция есть на бирже, нет в БД» → orphan);
сверка: сумма pnl_net закрытых = изменение баланса.

## Тесты отказов

Обрыв стрима посреди сессии; 5xx от API; таймаут; 429/превышение лимита;
перезагрузка сервера с открытыми позициями; недоступность VK; недоступность
дашборда (торговля продолжается); повреждение БД (WAL recovery);
двойной запуск второго экземпляра (защита lock-файлом).

## Тесты стратегии (не «сравнить с идеалом»)

- Фикстура-датасеты: сильный тренд, затяжной флэт, гэп, chaos, объёмный всплеск.
  Для каждого — ожидаемое множество сигналов, не «похожая кривая доходности».
- Проверка, что все 10 фильтров срабатывают изолированно (каждый по отдельности).
- Проверка journal: на каждый сигнал и каждый отказ есть запись с полным snapshot.
- Мультитаймфрейм: расхождение 1h блокирует вход на 5m.

## Оптимизатор

- L1: на синтетическом журнале с заведомо «плохой» комбинацией рекомендация указана верно.
- L2: веса не меняются при выборке < 50; не более 3 за цикл; автооткат при ухудшении;
  два отката подряд → уровень выключается.
- L3: на переобучающейся синтетике walk-forward должен **отвергнуть** набор, который
  идеален in-sample и плох in-forward. Это ключевой тест на защиту от подгонки.
- L3: при < 100 сделок цикл не запускается.

## Производительность и лимиты

- 30 тиков × 3 таймфрейма: расчёт индикаторов и scan < 200 мс (иначе не успеем к свече).
- Лимитер: 30-секундная имитация шквала запросов → очередь, приоритеты соблюдены.
- Решение оператора 2026-10-17 (+05): конкурентная загрузка истории сохраняет проверки каждой страницы, повторное чтение неполных историй в новом 15-минутном слоте и запрет partial pool. Проверить ограниченное число in-flight RPC, перекрытие сетевого ожидания и общий бюджет всех unary MarketData методов gateway (свечи/статусы/стаканы, включая retry): не более 600 стартов в любом скользящем окне 60 секунд. Часы лимитера — monotonic; lock не должен сериализовать сами RPC.
- Квотный retry: максимум 61 попытка всего на действие, пауза не меньше 1 секунды либо больше по server reset; длинный конечный reset не отклоняется только из-за прежнего бюджета 120 секунд. Общий cooldown соблюдают ожидающие запросы. UNAVAILABLE сохраняет отдельные bounded attempts/elapsed, авторизация не повторяется. Проверить смешанные статусы, exhaustion, отмену в очереди/ожидании/после RPC, отсутствие новых запросов после наблюдения отказа и отсутствие частичной публикации; уже начатые RPC могут завершиться.
- Сравнение скорости: одинаковый объём и latency фикстуры для одного и нескольких workers, wall-clock elapsed, реальные старты вызовов и peak in-flight. Это локальный benchmark с имитацией сети, не доказательство sandbox throughput; сетевое измерение оформляется отдельно от pytest, без заявок и без конкурирующего runtime.
- Память: 30 дней журнала не раздувают процесс (проверка RSS на фикстуре).

## Покрытие

Ориентир: `risk_manager`, `portfolio`, `security`, `broker` — ветвление близко к 100%;
остальной код ≥ 80%. Но покрытие — не самоцель: три ядерных инварианта выше процента.

## CI-минимум (`make ci`)
```
ruff check . && mypy --strict . && pytest -q
```
Падает на: красных тестах (кроме помеченных TODO(VERIFY)), появлении float в денежном
домене (grep-правило), наивном `datetime.now()`, `except Exception: pass`.
