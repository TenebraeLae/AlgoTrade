# 09_VK_NOTIFY — уведомления и удалённое управление

Бот работает автономно, человек не смотрит в дашборд круглосуточно. Канал — VK
(сообщение сообщества или диалог с ботом, LongPoll). Токен и peer_id — секреты, не в git.

## Входящий контур: LongPoll

- Долгий поллинг, обработчик событий, корректный `pts`, реконнект с backoff.
- **Whitelist:** команда исполняется, только если `peer_id` ∈ `VK_ALLOWED_PEER_IDS`.
  Чужой `peer_id` → игнорировать без ответа, записать в `event_log`. Публичного
  отклика «не та команда» нет: это разведка для посторонних.
- Дебаунс: не более N команд в минуту с одного peer, иначе лимит и предупреждение.
- Обработчик не должен блокировать торговый цикл: очередь сообщений, отдельная задача.

## Исходящий контур: что присылать

Реальное время:
```
OPEN SBER long 4 лота @ 312.40  (1 249.60 ₽)
причина: trending, EMA9×EMA21↑, RSI 52, MACD↑, close>VWAP, объём 1.8×
стоп 309.10  тейк 317.40  риск 1.0% (124.96 ₽)
```
```
CLOSE SBER +186.30 ₽ (+1.49%) за 24 мин | тейк-1
день: +412.70 ₽ | открытых позиций: 3
```
События: дневной лимит потерь, потеря/восстановление связи, смена режима на chaos,
kill switch, расхождение учёта, результаты оптимизации, прокси-предложение уровня 3.

Ежедневный отчёт (~23:55 МСК): P&L ₽ и %, число сделок, win-rate, средний профит/убыток,
profit factor, сравнение с IMOEX и альфа, баланс и свободные средства, статус бота,
число отклонённых сигналов с топ-3 причинами по фильтрам.

## Команды

| Команда | Действие | Ограничения |
|---|---|---|
| `/status` | баланс, позиции, P&L, режим, статус | read-only |
| `/report` | сводка с момента запуска | read-only |
| `/stop` | graceful shutdown с вопросом о позициях | подтверждение сообщением |
| `/panic` | kill switch: закрыть всё по рынку, отменить заявки | **без подтверждения**, всегда |
| `/resume` | выход из паузы | не снимает дневной лимит потерь |
| `/mode paper` | переключить в paper | мгновенно |
| `/mode live` | переключить в live | **запрещено из VK**: ответ со ссылкой на ручную правку конфига (см. AGENTS §4.1) |
| `/optimize` | запуск L1 (или L2, если включён) | L3 из VK не запускается |
| `/optimize_status` | результат последнего цикла | read-only |
| `/optimize_rollback` | откат к backup весов | L2 |
| `/help` | список команд | read-only |

`/panic` выполняется немедленно и всегда, включая момент без связи: заявка ставится
при первой возможности. Для возобновления — ручной перезапуск.

## Правила содержимого сообщений

- Никогда не печатать токены, ключи, salt, полные пути к БД.
- Коротко: до ~600 символов, табы/выравнивание текстом, не HTML.
- На русском; числа с разделителями; проценты 2 знака.
- В тексте указываеть причину решения — это отличает полезное уведомление от «купил».
- Сообщения идемпотентны: при ретраях не дублировать. Хранить `sent_message_ids`
  для критичных событий; при недоступности VK писать в лог и продолжать торговать.

## Тесты

- чужой peer_id не исполняет ни одной команды (включая `/panic`);
- `/mode live` через VK всегда возвращает отказ;
- `/panic` исполняется при недоступности остальной системы;
- сообщение не содержит подстрок, похожих на токен (regex-тест);
- перегрузка команды — в очередь, торговый цикл не блокируется.
