# 10_DASHBOARD — веб-интерфейс

FastAPI, порт 8080, за reverse proxy с авторизацией (см. 13_SECURITY).
Данные — WebSocket, обновление 1 Гц; страницы тяжёлые (графики) — по REST с кэшем.

## Экраны

**Главная.** Режим крупно (PAPER — жёлтый, LIVE — красный, никогда не одинакового цвета).
Баланс, свободные средства, P&L дня и с запуска в ₽ и %. Текущий статус:
торгует / ожидает сигнала / пауза с причиной (вне сессии, дневной лимит, нет кандидатов,
chaos, ошибка связи). Текущий режим рынка. Кнопки: Старт, Стоп, **PANIC** (крупная,
красная, с обязательным подтверждением на двойной клик), переключатель режима
(переход в live требует отдельного подтверждения и показывает сводку paper-периода).

**Позиции.** Тикер, направление, лоты, вход, текущая, P&L ₽ и %, дистанция до стопа/тейка,
время в позиции, состояние трейла, источник (`bot`/`restored`/`orphan`). Orphan — красным.

**Сделки.** Лента 20 последних + таблица с фильтрами по тикеру/дате/exit_reason.

**Статистика.** Всего сделок, win-rate, средняя прибыльная/убыточная, profit factor,
Sharpe (упрощённый, дневной), максимальная просадка, серия убытков.

**Графики.** Накопленный P&L по времени; линия IMOEX за тот же период; альфа отдельной
линией; гистограмма P&L по дням; распределение P&L по сделкам.

**Журнал решений.** 50 записей, раскрывающиеся: snapshot индикаторов, пройденные и
не пройденные фильтры, вердикт и причина. Это то, что человек читает, чтобы понять,
почему бот ничего не купил три часа.

**Оптимизация.** История прогонов L1/L2/L3, изменения и причины, метрики до/после,
статус откатов. Список `proposals` (предложения L3) с кнопками «Применить в live» /
«Отклонить» — единственный путь применения L3.

**Логи.** 20 последних событий, уровни цветом, выгрузка файла.

## REST

```
GET  /api/status          режим, баланс, позиции, статус, режим рынка
GET  /api/positions
GET  /api/trades?limit&from&to&exit_reason
GET  /api/stats?from&to
GET  /api/journal?limit&verdict
GET  /api/benchmark       кривые бота и IMOEX
GET  /api/optimizer/runs  /api/optimizer/proposals
POST /api/control/start|stop|panic
POST /api/mode/paper      /api/mode/live     (live — двойное подтверждение + токен-подпись)
POST /api/optimizer/proposals/{id}/approve|reject
WS   /ws                  статус, позиции, сделки, journal в реальном времени
```

## Правила

- Панель никогда не показывает цифру, которой нет в БД. Если данных нет — «нет данных»,
  а не ноль. Пустой дашборд честнее красивого.
- PANIC не зависит от доступности WebSocket и от состояния торгового цикла.
- Все POST требуют авторизации и CSRF-защиты; `/api/control/panic` допускает отдельный
  одноразовый код, если сессия протухла.
- Никакой правки конфига из UI, кроме переключения режима. Параметры риска не редактируются
  из веб-интерфейса (см. AGENTS §4.2).
- Страницы облегчённые: работает на телефоне в браузере, без внешних CDN и библиотек из интернета.

## Тесты

- эндпоинты возвращают ожидаемую схему на моках;
- PANIC проходит, когда торговый цикл «завис» (тест с имитацией блокировки);
- UI не содержит секретов (проверка HTML на токен-паттерны);
- нет данных → «нет данных», а не 0.
