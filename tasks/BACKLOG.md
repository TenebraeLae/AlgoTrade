- [ ] **API-A01 · P1 · M2 — Ограничить длительность каждого unary RPC.**
  - **Приёмка:** deadline задан на транспортном уровне для всех используемых unary RPC, включая каталог, счета и явно вызываемое открытие sandbox-счёта; значения конечные/положительные, вынесены в конфигурацию. Разделены deadline одной попытки, elapsed-budget `UNAVAILABLE` и общий quota cooldown. Долгий конечный server reset, в том числе >120 секунд, не обрезается и не расходует transport-budget; после ожидания отдельный RPC всё равно ограничен. Более короткий исходный timeout не увеличивается. Сохраняются отдельные retry-политики и mixed-status ограничения из `docs/15_ACCEPTANCE.md`, M3; `DEADLINE_EXCEEDED` не добавляется к retry автоматически, мутации с неизвестным результатом не повторяются вслепую. Отмена запрещает последующие вызовы; зависший RPC не удерживает worker бесконечно, claim/fill/complete/ack не разрывается.
  - **Regression:** задержанный локальный gRPC-сервис завершается по deadline; сохранение более короткого timeout; долгий reset >120 секунд с успешным продолжением и отменой во время ожидания; mixed quota/UNAVAILABLE; исчерпание бюджета не запускает новый RPC; `DEADLINE_EXCEEDED` без неутверждённого retry; timeout открытия sandbox-счёта ведёт к сверке, не повторному созданию; shutdown с in-flight RPC завершается ограниченно, без частичного пула; отмена при уже начатом paper fill сохраняет атомарное завершение claim/fill/complete/ack без повторного исполнения.

- [ ] **API-A03 · P2 · M3 — Подключить приоритеты и порог 80% к действующему limiter.**
  - **Приёмка:** расширить существующий общий thread-safe limiter, не заменяя доказанную защиту квоты старым fixed-window helper. Задать таблицу «назначение → приоритет» для bootstrap/refresh, истории стратегии/индекса, статуса и стакана: приоритет не определяется одним именем SDK-метода. Порог 80% относится к настроенному общему бюджету; учитываются страницы, повторы и pending/in-flight leases. Фоновые ожидающие запросы не захватывают срочный резерв заранее; приоритет учитывается при dispatch. Отказ admission означает defer, не пустую историю/исключение кандидата/частичный пул. Bootstrap/refresh продолжаются порциями по мере освобождения бюджета; определить и проверить политику против starvation с измеримой границей отсрочки при наличии доступного фонового бюджета, не отменяющую срочный резерв. При устойчивом исчерпании бюджета срочной нагрузкой диагностировать невозможность прогресса, а не обещать безусловное завершение. Срочные запросы не обходят общий cooldown и потолок 600 стартов в скользящих 60 секундах; ордерные квоты отдельно. Сохраняется политика повторов из `docs/15_ACCEPTANCE.md`, M3.
  - **Regression:** конкурентный фоновый шквал + срочный запрос; точные границы 80% настроенного бюджета и 600/60s; ожидающие фоновые leases не занимают весь резерв; длительная конкуренция и продолжение bootstrap/refresh через следующие окна; общий cooldown методов; отмена ожидающего запроса; retry не обходит лимит; defer не становится отсутствием истории или публикацией частичного пула.

- [ ] **API-A05 · P2 · M3 — Исправить lifecycle и классификацию отказов стрима.**

Отсутствие SDK, ошибки конфигурации и авторизации не повторяются; adapter сохраняет безопасную типизированную классификацию. - [ ] **API-A06 · P2 · M3 — Обрабатывать ACK, heartbeat и восстановление пропусков.**
  - **Приёмка:** использовать подтверждённые SDK `subscribe_candles_response`, `CandleSubscription.subscription_status` и `MarketDataResponse.ping`; до реализации закрепить тестами фактическую передачу/обработку этих событий SDK manager. Отрицательный ACK не считается успешной подпиской. Определить heartbeat-сигнал, владельца watchdog и конфигурируемый timeout по проверенной семантике; отсутствие свечей само по себе не равно обрыву. Watchdog обнаруживает зависание независимо от блокирующего чтения и обеспечивает ограниченное освобождение/остановку reader без утечки потоков/каналов. После reconnect — переподписка, backfill с общим unary limiter и дедупликация по инструменту/таймфрейму/времени открытия; неполное восстановление не разрешает входы. Конфликтующие дубли внутри одной загрузки не становятся молчаливым last-write-wins. Wiring в polling-runtime и сверка заявок/исполнений/позиций не считаются выполненными этой задачей; торговая сверка остаётся M8.

  - **Regression:** плотная и разреженная история; границы страниц; идентичные/конфликтующие дубли; пустая и усечённая страница; системный отказ без частичной публикации в bootstrap и refresh; неполная история перечитывается в следующем слоте. Отдельный read-only sandbox-прогон с зафиксированными параметрами: до запуска описать контрольный набор и метод сравнения (например, разбиение тех же дат на меньшие окна с сопоставлением ключей/OHLCV), отдельно оценить прохождение диапазона и достаточность истории для caller. Сравнение разных окон одного API — проверка согласованности, не абсолютное доказательство отсутствия усечения; неразрешённую неопределённость записать явно. Mock усечения не доказывает обнаружение произвольного незаявленного серверного пропуска, mocks не заменяют сеть.
