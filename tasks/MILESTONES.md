# MILESTONES — порядок сборки

Порядок выбран так, чтобы дорогие ошибки всплывали до появления реальных заявок.

| Этап | Что | Почему именно здесь |
|---|---|---|
| **M0** | Каркас репозитория, Docker, линт, тест раннер, CI-скрипт | Без фундамента каждая следующая задача дороже |
| **M1** | `security.py`: шифрование токена, маскирование в логах | Секреты не должны ни разу попасть в открытый вид |
| **M2** | `api_client.py`: подключение, список счетов, инструменты, **все вызовы через адаптер + TODO(VERIFY)** | Здесь кончаются догадки об API. Дешевле проверить сейчас, чем чинить в M7 |
| **M3** | `market_data.py`: свечи, кэш с TTL, rate limiter, stream котировок | Данные первичны; без лимитера всё дальше будет падать на 429 |
| **M4** | `indicators.py` + golden-тесты на синтетических данных | Индикаторы проверяются без брокера. Ошибка здесь — тихая и дорогая |
| **M5** | `risk_manager.py`: размер позиции, стопы, дневные лимиты, 12 проверок | **Ключевой этап.** Делается до стратегии, а не после |
| **M6** | `paper_broker.py` + `portfolio.py`: виртуальные заявки, сделки, учёт, восстановление состояния | Здесь рождается журнал, из которого потом считается всё |
| **M7** | `strategy.py`: режимы рынка, сигналы, фильтры, journal решений | Стратегия теперь крутится вокруг корректного учёта и риска, а не наоборот |
| **M8** | `executor.py`: paper/live развилка, частичные исполнения, реконнект, восстановление после сбоя | Живой контур. Реальные заявки — только после M7 принят |
| **M9** | `dashboard.py` + `vk_bot.py` + kill switch + graceful shutdown | Управление и наблюдаемость. Без них бот не запускается человеком |
| **M10** | `optimizer.py`: уровень 1, затем 2, затем 3 (paper-only) | Оптимизировать нечего, пока нет журнала и статистики |

## Правила перехода между этапами

1. Этап не считается завершённым без пунктов `docs/15_ACCEPTANCE.md`.
2. **M8 не начинается без письменного подтверждения оператора.** Это первый этап,
   где код получает физическую возможность отправить заявку.
3. **M10 уровня 3 не может быть принят без 30 дней работы в paper с журналом ≥200 сделок.**
4. Возврат на предыдущий этап разрешён и нормален. Возврат фиксируется в CHANGELOG.

## Анти-паттерны плана

- Начать со стратегии («давай сразу сигналы») — приведёт к переписыванию учёта.
- Делать дашборд раньше портфеля — дашборд начнёт показывать выдуманные цифры.
- Писать оптимизатор «когда-нибудь потом одним куском» — журнал придётся вести задним числом,
  контекст сигналов уже не восстановить.
- Один этап = один большой PR. Реальный риск: не разобрать, что сломалось.
